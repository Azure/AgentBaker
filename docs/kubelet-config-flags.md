# Linux kubelet renderer omission contract

This is default-off renderer support, not Kubernetes-version policy or config-mode activation. An upstream producer must choose the supported node version, effective settings and compatible provisioning artifacts before using it. Existing callers that do not send the new instruction retain their existing kubelet output, even when config-file mode is already enabled.

## Request

Set `enabled_features["KUBELET_FLAGS_TO_OMIT"]` in the direct AKSNodeConfig selected for Phase 3 execution. Its value is an **unpadded standard-base64** encoded JSON string array of full flag names, at most 1024 encoded bytes and 16 entries. Go producers can use `base64.RawStdEncoding.EncodeToString`. For example, encode `["--enable-server","--runtime-request-timeout"]`. The Linux renderer also accepts/restores padding on valid standard-base64 inputs. Values and config mode remain producer-owned.

The producer selects the subset; no flags are selected automatically. Unknown names are ignored. Malformed/oversized lists, missing or nonmatching fields, config-off and an alternative `--config`/`--config-dir` in custom flags preserve the existing arguments. Empty/absent instructions do nothing, except removing this renderer's own previous override during rollback.

## Replacement checks

The loaded `/etc/default/kubeletconfig.json` and its standard config drop-in must exist. Each requested name is omitted only for this explicit matching value:

| Requested local argument | Required config value | Versioned upstream deprecation evidence |
|---|---|---|
| `--enable-server` | `enableServer: true` (missing/false is not a match) | [v1.19.0](https://github.com/kubernetes/kubernetes/blob/v1.19.0/cmd/kubelet/app/options/options.go#L403), [v1.37.0](https://github.com/kubernetes/kubernetes/blob/v1.37.0/cmd/kubelet/app/options/options.go#L364) |
| `--volume-plugin-dir` | `volumePluginDir: /etc/kubernetes/volumeplugins` | [v1.19.0](https://github.com/kubernetes/kubernetes/blob/v1.19.0/cmd/kubelet/app/options/options.go#L470), [v1.37.0](https://github.com/kubernetes/kubernetes/blob/v1.37.0/cmd/kubelet/app/options/options.go#L436) |
| `--cgroup-driver` | `cgroupDriver: systemd`, `NEEDS_CGROUPV2=true`, recognized cgroup drop-in | [v1.10.0](https://github.com/kubernetes/kubernetes/blob/v1.10.0/cmd/kubelet/app/options/options.go#L518), [v1.37.0](https://github.com/kubernetes/kubernetes/blob/v1.37.0/cmd/kubelet/app/options/options.go#L452) |
| `--runtime-request-timeout` | `runtimeRequestTimeout: 15m` | [v1.10.0](https://github.com/kubernetes/kubernetes/blob/v1.10.0/cmd/kubelet/app/options/options.go#L522), [v1.37.0](https://github.com/kubernetes/kubernetes/blob/v1.37.0/cmd/kubelet/app/options/options.go#L459) |
| `--container-runtime-endpoint` | `containerRuntimeEndpoint: unix:///run/containerd/containerd.sock` | [v1.27.0](https://github.com/kubernetes/kubernetes/blob/v1.27.0/cmd/kubelet/app/options/options.go#L372), [v1.37.0](https://github.com/kubernetes/kubernetes/blob/v1.37.0/cmd/kubelet/app/options/options.go#L379) |

These registrations belong to the [deprecated config-flag family](https://github.com/kubernetes/kubernetes/blob/v1.37.0/cmd/kubelet/app/options/options.go#L334). Deprecation evidence does not establish availability or validation of a future binary.

The renderer never rewrites `KUBELET_FLAGS`, including duplicate/custom arguments; they remain last and retain their precedence. Alternate duration spellings such as `15m0s` conservatively retain the timeout flag. Nonmatching fields do not authorize a behavior change. Reserved-cgroup/hardening policy, runtime-cgroup selection, TLS/bootstrap, IMDS restriction, networking and sandbox-image configuration are unchanged.

## Provisioning and rollback

`ensureKubelet` reconciles `11-kubelet-config-flags.conf` after the existing final runtime writer and before daemon-reload/start. This is in real-node `nodePrep`, including PIS nodes that skip `basePrep`. The globally baked service and original drop-ins stay unchanged. Reconciliation is idempotent; dropping the instruction or disabling config mode removes only this managed override. A functional ownership header records the SHA256 of the exact generated body. Only an unchanged regular file with that matching header can be removed or replaced; unmarked, edited and symlink collisions are preserved even with an explicit request. Writes use a mode-0600 temporary file and atomic rename in the same directory. Failed replacement preserves the prior file.

All omissions require the exact checked-in `kubelet.service` (SHA256 `98172d7111cb1d7d9b9b8469ca1a7bd2aebbb0a48bc8f6633c5210f4df7dd1e9`) or its comment-stripped CustomData form (`e05dba2eee92f4c56c5dd3ff072b745b06c80a3399d0401ae50440a723db9e97`), not just a matching `ExecStart`. Any future service change requires separate validation before updating these fingerprints. Config, runtime, cgroupv2 and TLS-bootstrap environment drop-ins must match their recognized bodies. Runtime-cgroup output must match the persisted final writer, including its hardened slice selection. Only the shipped watchdog, bindmount dependency, reserved slice, credential-validation and IMDS drop-in names/bodies are additionally accepted, with constrained hostname/IP/boolean slots for their existing values.

Any other drop-in, extra directive or symlink in kubelet or global `service.d` directories retains **all** arguments. This includes later `20-custom.conf` environment assignments/files, resets, `PassEnvironment`, `UnsetEnvironment`, `RootDirectory`, bind-path changes and custom `ExecStartPre` commands. Unknown directives are not interpreted or individually classified as safe. Tests execute the baked helper through both the VHD hook and its traditional CustomData form, including rollback.

The scan covers the default system unit paths, including control, transient, attached and all three generator directories. A whole `kubelet.service` in either `system.control` directory, `transient` or `generator.early` also retains all arguments because it precedes the fingerprinted `/etc/systemd/system/kubelet.service`. See the system unit search paths in [systemd v249](https://github.com/systemd/systemd/blob/v249/man/systemd.unit.xml#L40) and [v255](https://github.com/systemd/systemd/blob/v255/man/systemd.unit.xml#L41). Custom manager search paths such as `SYSTEMD_UNIT_PATH` are outside the qualified layout.

The checked base service must be a regular file, not a symlink. Any service symlink in those default directories that resolves to the same base file also retains all arguments: systemd can load drop-ins under the alias name. Unrelated service aliases do not disable rendering.

The base `EnvironmentFile=/etc/default/kubelet` is inspected on disk, independently of the CSE shell environment. It must contain one `KUBELET_FLAGS` assignment and only the existing writer's single-line fields. Alternative `--config`/`--config-dir`, extra environment names, quoting and continuations conservatively retain all arguments. Supported raw/custom flags remain byte-for-byte untouched, including duplicates and values that differ from CSE's environment.

**Unsupported custom surfaces:** additional kubelet `EnvironmentFile` directives always retain all flags, even if the file currently looks harmless or is optional/missing. This deliberately includes `10-httpproxy.conf` loading `/etc/environment`; proxy nodes are not claimed migrated. The secure-TLS bootstrap environment file belongs to `secure-tls-bootstrap.service`, not kubelet, and does not affect this decision. Loading that or any other extra environment file into kubelet instead falls back. This is a prerequisite for known provisioning artifacts, not a general systemd parser or migration of custom service-manager/root-filesystem configurations.

## Supported delivery paths and prerequisites

- **Direct typed ANC:** `BuildCSECmd` reads this reserved key from the current typed configuration and removes any inherited copy. Absent, empty or multiline values cannot reuse an old launcher instruction. Other single-line values pass through unchanged; the renderer validates the bounded list. No other feature keys are newly exported. The existing typed kubelet serializer supplies the replacement values.
- **NBC fallback and compare mode:** no omission instruction or config translation is added to the legacy command. When ANC chooses NBC, it explicitly clears the reserved environment key before executing the command, including an instruction inherited from an old `enabled_features.sh`. The compatible final hook still runs with the empty instruction and removes only an owned override. Compare mode still executes NBC and compares environment strings afterward; this change does not suppress those diagnostics.
- **VHD delivery:** `kubelet-flags.sh` is baked beside `provision_configs_kubelet.sh` using the Packer/imagecustomizer mappings. The small final hook sources it when present. Its body is not included in traditional CustomData, which retains gzip file encoding. The hook changes those script bytes but does not choose any flags. Missing helpers leave existing files alone; they cannot clean up a previously owned override.

The initial producer cohort is direct Linux Phase 3 with stable actual-node Kubernetes >=1.38, an explicit rollout toggle and an exact qualified image. Flatcar, ACL, Windows, original NBC-conversion paths and PIS activation remain outside that cohort. PIS tests protect the final hook and fallback ordering; they do not qualify PIS activation. Rollout is planned for Q1 2027 or later and still requires release and runtime qualification.

Qualification must include the ANC binary's typed-instruction and NBC-clear behavior, the baked helper, the final hook and the recognized service layout. Traditional `nodecustomdata.yml` can overwrite `provision_configs_kubelet.sh`, `provision_configs.sh` and `provision.sh` from the linked AgentBaker library. Embedded script hotfixes can overwrite those files too; custom script paths can bypass them. Only versions that preserve the hook and helper are supported on reused nodes. Exclude old/custom overwriters and helper-removing downgrades; before any such downgrade, use compatible scripts with omission disabled to remove the owned override or replace the node. Merely upgrading the ANC binary does not update these scripts. Existing embedded-hotfix delivery is not a new installer for this helper.

No producer activation, legacy migration or schema changes are included. A missing helper on a fresh node preserves the local arguments; a missing helper on a node with a prior override is not a supported rollback path. Older/prerelease/default/override behavior and runtime-cgroup selection remain unchanged. The small shared hook is a compatibility requirement to review with Node Lifecycle before release.

Local tests cover rendering, transport, boundaries, fallback, PIS ordering and reversible output. They do not prove matching future Kubernetes binary acceptance, node readiness, networking/security equivalence or all historical VHD combinations. Linux support does not imply Windows parity.
